## Why a checklist, and why yours

A file checklist turns the monitor's questions into a list your staff can work from every day. It only helps if it matches your board's actual monitoring tool and local policies, so build it from those sources instead of copying another agency's form.

Start from three documents:

- Your board's local monitoring tool (the items the local monitor scores).
- Your board's local policies for eligibility, training, supportive services, and case management.
- The state's current acceptable documentation guidance for eligibility elements.

## Building the checklist

Organize the checklist in the order a file is built, so a case manager can use it from intake to exit. Each line should be checkable: someone else could look at the file and agree or disagree.

| Section | Checklist item | Source to confirm | Y / N / NA |
| --- | --- | --- | --- |
| Eligibility | Each eligibility element has acceptable documentation in file | State documentation guidance; local policy | |
| Eligibility | Documents dated on or before eligibility determination | Local monitoring tool | |
| Data | CalJOBS enrollment, service, and exit dates match file | Local monitoring tool; DEV guidance | |
| Assessment | Objective assessment completed and in file | Local policy | |
| Plan | IEP/ISS signed, goals support planned services | Local policy | |
| Training | Need for training documented in case note | Local policy | |
| Training | Provider and program on the ETPL (or other allowed basis) | Local policy | |
| Supportive services | Need, approval, and receipt for each payment | Local supportive services policy | |
| EO | Signed EO notice acknowledgment | Your EO procedure | |
| Case notes | Notes at the frequency your local policy sets | Local policy | |
| Exit | Exit consistent with last service; follow-up documented | Local policy | |

Two rules keep the checklist useful:

1. **Name the source.** If a line cannot be traced to a policy or the monitoring tool, it is either a local best practice (label it that way) or it should come off.
2. **Keep it current.** When your board issues or cancels a policy, update the checklist the same month and date the version at the top.

## Designing a sampling routine

You cannot review every file every month, and you do not need to. A sampling routine reviews a predictable number of files on a predictable schedule, chosen so that no program, staff member, or file stage is skipped for long.

Decide five things and write them down:

| Decision | Questions to answer | Example (Valley Regional) |
| --- | --- | --- |
| Frequency | How often do you review? | Monthly |
| Size | How many files per cycle? | 10 files per office |
| Selection | How are files picked? | Random from active and recently exited, at least one per case manager |
| Coverage | What must every cycle include? | Adult, dislocated worker, and youth; at least two training files |
| Reviewer | Who reviews, and can it be someone other than the file owner? | QA analyst; supervisors swap offices |

There is no single correct sample size. Your board's local policy or contract may set a minimum; if it does, follow it. If it does not, pick a size you can actually sustain, because a routine you skip is no routine at all.

To pick files randomly, export the list of eligible participant IDs from CalJOBS into a spreadsheet, add a column with a random number, sort by it, and take the top rows. Record the export date and the IDs selected so the sample can be shown to a monitor later.

## Recording and using results

A review only counts if it is recorded. For each cycle, keep:

- The sample list and how it was drawn.
- A completed checklist per file.
- A one-page summary: files reviewed, items failed, error rate by checklist item.
- The fix for each failed item and the date it was fixed.

Look at results by item, not just by file. If four of ten files miss the training-need case note, that is a process problem, not four individual mistakes. That pattern is what feeds a corrective action plan in Lesson 5.

## Worked example: one cycle's summary

| Checklist item | Files failed (of 10) | Action |
| --- | --- | --- |
| Training need documented | 4 | Refresher at team meeting; recheck next cycle |
| EO acknowledgment signed | 2 | Corrected in files; add to intake packet checklist |
| CalJOBS exit date matches | 1 | Corrected in CalJOBS; note in file |

## Discussion prompt

How many files does your office review internally each month today? Who reviews them, and what happens to the results after the review?

## Practice

1. Draft a one-page file checklist for one program you oversee. Give every line a source from your board's monitoring tool or local policy, or label it "local best practice."
2. Write your sampling routine using the five decisions in the table above. Keep it to half a page.
3. Run a trial: draw a random sample of five files from a CalJOBS export using the spreadsheet method, review them with your checklist, and produce the one-page summary by item.
