## Description

As a QA software engineer, the tools in this course are not optional extras — they are how you do the job every day. Git is the record of what changed and why, and it is the surface you read before you can review anyone else's work. Chrome DevTools is the instrument you reach for the moment a page misbehaves, whether that means inspecting markup, reading a console error, or timing a slow network request.

This course builds those two toolsets from the ground up. You will start with a working local environment and dependable version-control habits, move into reviewing other people's changes and documentation, then spend real time inside DevTools learning to isolate problems and audit quality. The back half turns that investigative skill into something a team can act on: a well-written defect report, and a real deployment you verify yourself.

By the end, you will be able to set up an environment, track and recover work in Git, participate credibly in a pull-request review, diagnose a broken page using DevTools evidence, write up what you found so a developer can fix it without guessing, and confirm a live deployment behaves as intended.

## Objectives

- Set up a local development environment that mirrors how the project really runs
- Use Git to record, inspect, and recover work
- Work on a shared repository using branches, merges, and pull requests
- Review a change and its documentation for accuracy and completeness
- Use Chrome DevTools to inspect and debug a running page
- Audit a page's network activity, performance, and accessibility from the browser
- Turn what DevTools shows you into a defect report a developer can act on
- Deploy a site publicly and verify it behaves as expected
