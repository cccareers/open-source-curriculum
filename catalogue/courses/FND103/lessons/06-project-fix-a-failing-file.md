## Goal

Repair a fictional participant file so that it would pass a validation review. You will rewrite the plan, the case notes, and the activity dates, and you will document every correction so a reviewer can follow what changed and why.

## The case

You have just inherited the caseload of a case manager who left the Valley Regional Workforce Board. One file belongs to **Rosa, 41, a dislocated retail store manager** enrolled in the Dislocated Worker program and placed in a bookkeeping certificate program.

What you find in the file:

- **IEP:** "Rosa wants an office job. Good with numbers. Enroll in bookkeeping." No assessment results are referenced, although the file contains a basic skills test report with math scores that meet the provider's entry level and an interest inventory ranking business operations first.
- **Work history:** 12 years in retail, the last 5 as store manager responsible for daily cash reconciliation and weekly inventory reports.
- **Training activity:** begin date January 6 (voucher issue date). The provider roster shows first attendance January 21. Projected end date April 30. The provider emailed in March that the cohort now ends May 16. The projected end date was never updated.
- **Case notes:**
  - January 8: "Rosa is excited. She'll do great."
  - February 27 (entered March 20): "Checked in, all good."
  - No notes for March or April.
- **Supportive service:** transportation assistance activity entered February 3. No note or receipt in the file.

## Requirements

1. **Rewrite the IEP** goal, interest, aptitude, and skills sections so each claim points at evidence in the file, and state why training (not OJT) closes Rosa's gap.
2. **Rewrite the two existing case notes** so they are factual and use the contact, service, outcome, next-step pattern. Where facts are missing, write [missing: describe it] rather than inventing them.
3. **Correct the training activity dates:** the begin date, the projected end date, and a plan for recording the actual end date.
4. **Write a correction note** for each date change, naming the source document.
5. **Fill the documentation gap** for the supportive service: state what document and note the file needs.
6. **Complete a self-audit table** tracing at least four data elements from system value to source document.

## Constraints

- Use only the facts given above. Do not invent attendance, test scores, or receipts to make the file pass.
- Do not backdate notes. Corrections are new notes dated today that explain what changed.
- Treat documentation requirements as local and state variables: where you'd need a rule (for example, which receipt is acceptable for a transportation payment), write "check [source]" instead of guessing.

## Definition of Done

- The IEP names the evidence behind interest, aptitude, and skills.
- No case note contains an opinion about Rosa's character or likely success.
- Every activity in the file has a supporting note, and every service note maps to an activity.
- Begin date matches the roster; the projected end date reflects the provider's March notice.
- The self-audit table has no unexplained "No."
- A colleague who has never seen the file can explain from your work what happened and what comes next.

## Hints

- Start with the dates. They are the easiest errors to prove and the most likely to fail.
- Rosa's cash reconciliation and inventory reporting are transferable skills; use them in the skills section.
- The March gap in notes is a risk for inactivity-driven closure. Your next-step entries should show ongoing engagement.
- Reread the eight recurring errors from the previous lesson and check your finished file against each one.
