## Description

IT Service Management is the part of ServiceNow that most organizations buy first and live in every day. When someone's laptop dies, when a recurring outage finally gets a root cause, when a firewall rule needs an approval before it ships, when a new hire needs six things provisioned on day one — all of that lands in ITSM. Your job as an implementation specialist is to configure the platform so those processes run correctly, measurably, and without a customization that breaks the next upgrade.

This course takes you through that work in the order the processes actually depend on each other. You will start with the vocabulary and the data model, because "configure incident management" means nothing until you and the customer agree on what an incident is and which table holds it. From there you configure incident, problem, and change; customize the forms and tables those processes run on; build a service catalog that produces correct request and task records; attach SLAs that measure a real commitment; and automate the whole thing with Flow Designer and business rules.

The last three lessons handle what ITSM leans on rather than what it is. You will model configuration items and asset lifecycles well enough that ITSM processes can trust the CMDB, connect ITSM to an external system over REST, and watch that integration once it is live. The course closes with a project where you implement one process end to end and defend the configuration decisions you made.

## Objectives

- Map the ITIL practices an organization runs onto the ServiceNow tables that support them
- Configure incident management including states, priority, assignment, and major incident handling
- Configure problem management and connect it to incident and change records
- Configure change management with change types, approvals, and a change schedule
- Customize forms, fields, and tables for an ITSM requirement without breaking upgradeability
- Build catalog items, variables, and order guides that produce correct request and task records
- Define SLAs, OLAs, and schedules that measure the commitment the business actually made
- Automate an ITSM process end to end with Flow Designer and business rules
- Model configuration items, relationships, discovery, and asset lifecycle so ITSM processes can rely on the CMDB
- Integrate ITSM with an external system and monitor the integration once it is live
