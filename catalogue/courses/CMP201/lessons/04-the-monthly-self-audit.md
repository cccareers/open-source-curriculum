## Why monthly

The annual DEV review gives you a short document window and a sample you don't choose. If you find a problem then, you are fixing it under a deadline, often for a participant who exited months ago. A monthly self-audit moves that work to a time when the case manager still remembers the participant, the provider still has the roster, and a correction can be made calmly.

The goal is not to audit everything. It is to pull a small, regular sample, check it the same way a reviewer would, and track which elements keep failing.

## Who does what

| Role | Monthly job |
| --- | --- |
| MIS administrator | Draws the sample, keeps the results log, reports trends |
| Supervisor | Reviews results with the team, assigns fixes, checks they're done |
| Case manager | Fixes their own files, writes the case note explaining each fix |

In a small office one person may wear two hats. Avoid having case managers audit only their own files; a second set of eyes catches what the author can't see.

## The routine, step by step

1. **Draw the sample.** Pull a small set of records at random from the current reporting period. Your board's local policy sets the size; many offices pick a few files per case manager. Mix programs (Adult, Dislocated Worker, Youth) and include some exiters.
2. **Use the checklist.** Work through the CCC checklist below for each file. Use the same element list EDD uses for your program, from the current validation directive.
3. **Match each element.** For every element: system value, document, same value? Use the three moves from the previous lesson.
4. **Log results.** One row per element per file: pass, fail, or "needs check."
5. **Calculate element error rates.** Same formula DEV uses: failed divided by reviewed, per element.
6. **Route fixes.** Every fail goes to the case manager with a due date. Anything that needs a change to a locked or reported record goes through the correction process covered in the next lesson.
7. **Close the loop.** Next month, re-check last month's fails before drawing the new sample.

## Sample CCC self-audit checklist

Use this as a starting template and adapt it to your program's element list.

```text
CCC MONTHLY FILE SELF-AUDIT
Board: ____________   Month: ________   Reviewer: ____________
Participant ID: ________   Program: Adult / DW / Youth   Exited? Y / N

For each element: record system value, document found, and result.

[ ] Date of birth .................. value ____ doc ____ P / F / ?
[ ] Eligibility category ........... value ____ doc ____ P / F / ?
[ ] Employment status at entry ..... value ____ doc ____ P / F / ?
[ ] Highest grade completed ........ value ____ doc ____ P / F / ?
[ ] Training begin / end dates ..... value ____ doc ____ P / F / ?
[ ] Credential attained ............ value ____ doc ____ P / F / ?
[ ] Exit date ...................... value ____ doc ____ P / F / ?
[ ] Employment after exit .......... value ____ doc ____ P / F / ?

Can every document above be found in under 5 minutes?  Y / N
Fixes assigned to: ____________   Due: ________
```

The "under five minutes" line matters. If you can't find a document quickly now, you won't find it inside the 15-business-day window either.

## Reading the log

After three or four months, the log tells you where to put training time.

| Element | Reviewed (3 months) | Failed | Error rate |
| --- | --- | --- | --- |
| Training begin date | 18 | 4 | 22% |
| Employment status at entry | 24 | 1 | 4% |
| Credential attained | 10 | 2 | 20% |

At Valley Regional, the supervisor sees training begin date failing well above the 10 percent threshold the course description names. She traces the fails to one provider whose roster arrives late, so staff were using the voucher date. The fix is a process change with that provider, not a reminder email.

## Discussion prompt

If you could check only three elements every month, which three would you pick for your office, and why?

## Practice

1. Copy the checklist above and edit the element list to match your program's elements in the current EDD validation directive.
2. Decide your monthly sample size and write down who draws it, who reviews, and who fixes.
3. Run the checklist on two training sample files (or closed files you are authorized to review). Log every element and calculate an error rate for any element you checked in both.
4. Write a three-sentence note to your supervisor naming the one element you would watch most closely.
