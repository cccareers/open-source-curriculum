## The rule behind every match

For each data element, state guidance lists the source documents that can support it. The course description points to **WSD22-15** for source-document requirements. That list is your answer key. Nothing else counts: not a supervisor's memory, not a document that "should be good enough," not the practice the last case manager followed.

This lesson teaches you a way to match elements to documents quickly and to spot a weak match before a reviewer does. Keep the current list open while you work. The examples below show the *kinds* of documents that appear on acceptable lists. Confirm every specific document against the current WSD22-15 list and any later EDD updates before relying on it.

## Four kinds of support

Most acceptable documents fall into one of four kinds. Knowing the kind tells you what a good document looks like.

| Kind | What it is | What makes it pass |
| --- | --- | --- |
| Official record | A document issued by an agency, school, employer, or provider | Readable, about this person, and showing the value reported |
| Data match | A cross-check against a state or federal database | A record of the match (screen print or report) in the file, dated |
| Self-attestation | The participant's signed statement | Only where the list allows it for that element; signed and dated |
| Case note | Staff documentation of a fact or service | Only where the list allows it; specific, dated, written at the time |

The two most common mistakes are using self-attestation or a case note for an element where the list does not allow them, and treating "we checked the database" as proof when no record of the check is in the file.

## Commonly failed elements

These elements show up again and again in validation problems. The middle column lists document types you will often see on acceptable lists. Your job is to confirm each against WSD22-15.

| Element | Document types often listed (confirm in WSD22-15) | Where matches break |
| --- | --- | --- |
| Date of birth | Government-issued ID, birth certificate, passport, other official records | Typo in system date; ID illegible in the scan |
| Selective Service registration (where required) | Registration verification from the Selective Service System | No printout in file; status not checked for the right age group |
| Low-income status | Public assistance records, income documentation, other items on the list | Income period doesn't match the determination; wrong household size |
| Dislocated worker status | Layoff notice, employer letter, UI records | Letter has no layoff date; system date doesn't match the notice |
| Employment status at entry | Pay stubs, employer verification, UI records, self-attestation where allowed | Status at entry recorded from a later date |
| Highest school grade completed | Diploma, transcript, self-attestation where allowed | Equivalency recorded as diploma, or the reverse |
| Training begin date | Provider attendance or enrollment records | Date taken from voucher or registration, not first attendance |
| Credential attained | Copy of credential, provider or licensing record | Credential name or date differs from the system |
| Employment after exit | Wage record match, employer verification, follow-up documentation | Follow-up note with no employer or date detail |

If an element you work with is not on this table, use the same method: find it on the list, note the allowed kinds, then check the file.

## Matching in three moves

For each element in a file:

1. **Find the value.** What does the system say? Write it down exactly: date, code, or name.
2. **Find the document.** Is there a document of an allowed kind for this element?
3. **Compare.** Does the document show the same value? Same date, same name spelling, same credential title?

### Worked example

Maria, a laid-off medical billing clerk, is enrolled as a Dislocated Worker at Valley Regional.

| Element | System value | Document in file | Verdict |
| --- | --- | --- | --- |
| Date of birth | 04/12/1984 | Driver's license, DOB 04/12/1984 | Pass |
| Dislocated worker status | Layoff 06/30 | Employer letter, layoff 06/30 | Pass |
| Employment status at entry | Employed | Same employer letter | Fail: she was laid off before entry, so "employed" disagrees with the letter |
| Highest grade completed | Associate degree | Self-attestation form | Check: is self-attestation allowed for this element? If not, fail |

## Discussion prompt

Which element in your office relies most on a document that comes from outside your agency? How long does it take to get a copy?

## Practice

Build a one-page matching reference for your own desk.

1. Pick the six elements your program reports that worry you most.
2. For each, copy from the current WSD22-15 list every acceptable document type.
3. Add a column for "where it breaks in our office."
4. Then test it: pull one real (closed, appropriately handled) file or a training sample file and run the three moves on each of your six elements. Record pass, fail, or "check."
