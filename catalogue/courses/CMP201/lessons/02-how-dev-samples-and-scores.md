## Why DEV exists

Your local area reports participant data to the state, and the state reports it to the U.S. Department of Labor through the PIRL. Those records drive the performance numbers your board is judged on. Data Element Validation (DEV) is the check that the reported values are real: that a reviewer can open a participant's file and find a document that supports what the system says.

The federal framework for validating performance data is in TEGL 23-19 and its changes. The course notes point out that TEGL 23-19 Change 3 expects annual validation training, which is one reason this course exists. In California, EDD runs the annual DEV review of local areas. Read the current EDD validation directive for your program year before every cycle, because the details change.

Keep one idea in front of you for the whole course: **DEV checks the record against the evidence.** It does not re-decide eligibility or judge the quality of the service. A participant who was truly eligible can still fail an element if the file can't prove it.

## Step 1: The sample

DEV does not look at every file. EDD draws a sample of participant records from what your area reported. You do not choose which files are pulled, and you should assume any reported record can be picked.

What you need to know about the sample:

| Question | What to do |
| --- | --- |
| Which records can be sampled? | Assume any record in the reporting period. Confirm the population (for example, exiters versus all participants) in the current EDD directive. |
| How many records? | Set by EDD's sampling method, not by you. Don't plan around a number from memory; check the directive. |
| Which elements are checked? | A defined list of data elements, which can differ by program (Adult, Dislocated Worker, Youth). The directive lists them. |

The practical lesson: the sample is a random draw, so the only safe strategy is for every file to be ready.

## Step 2: The document window

Once you receive the sample list, your area has a limited time to produce the source documents. The course description refers to this as the **15-business-day document window**. Confirm in the current directive when the clock starts and how documents must be submitted.

Fifteen business days sounds like plenty. It isn't if documents are in a provider's office, a former case manager's desk drawer, or a scanned folder with no naming convention. A document that exists but can't be found in time scores the same as a document that never existed.

## Step 3: Scoring each element

For each sampled record, the reviewer takes each selected data element and asks two questions:

1. **Is there an acceptable source document in the file for this element?**
2. **Does the document support the value reported in the system?**

Both answers must be yes for the element to pass. Common ways an element fails:

- No document at all.
- A document is present but isn't an acceptable type for that element.
- The document disagrees with the system: a different date, a different credential name, a different employment status.

Each element is scored pass or fail on its own. One record can pass eight elements and fail two.

## Step 4: The error rate

Results are rolled up **by element**, across all sampled records. For each element:

```text
error rate = elements that failed / elements that were reviewed
```

The course description names a **10 percent error threshold**. An element whose error rate exceeds the threshold is the one that draws attention and typically requires a corrective response. Check the current directive for exactly how the threshold is applied and what follow-up it triggers.

### Worked example

Valley Regional Workforce Board has 40 records sampled. Training begin date is reviewed on 32 of them (the other 8 had no training).

| Element | Reviewed | Failed | Error rate |
| --- | --- | --- | --- |
| Date of birth | 40 | 1 | 2.5% |
| Training begin date | 32 | 5 | 15.6% |
| Credential attained | 20 | 2 | 10.0% |

Training begin date is clearly over the line. Credential attained sits right at it, so one more failure would push it over. Date of birth is healthy. Notice that a small denominator makes each failure count more: with only 20 credential records, every miss moves the rate by 5 points.

## Discussion prompt

Which of your elements has a small denominator in a typical year? What does that mean for how carefully you check it?
