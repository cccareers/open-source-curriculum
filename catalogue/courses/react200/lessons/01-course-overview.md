## Description

You can already build a React component, feed it props, hold state in it, and fetch data into it. That is enough to build one screen. It is not enough to build an application, because an application has more than one screen and has state that no single component owns. This course is about what changes when the app grows past what one component tree can hold.

Two libraries carry most of that weight, and you will learn both properly rather than superficially. React Router turns the address bar into part of your application's state, so a page can be linked to, bookmarked, refreshed, and shared. Redux Toolkit gives you one place where data lives, so a cart, a session, or a filter does not have to be threaded through six components that do not care about it. You will build with the modern versions of both: the data-router API with loaders and actions, and Redux Toolkit slices and thunks rather than hand-written reducers.

The last third of the course changes posture. An apprentice usually joins a codebase rather than starting one, and the skills that matter there are different: writing an implementation plan a senior developer can actually approve, relaying a requirement accurately from a project manager to UX and QA, and taking a directed change through an app you did not write without breaking things that were working. You will do all three against real React code, not as a paperwork exercise.

## Objectives

- Add client-side routing to a React application
- Compose nested routes and layouts around shared data
- Manage application state in a central store
- Handle asynchronous work and side effects in a state container
- Produce an implementation plan for a multi-feature application
- Relay requirements between a project manager, UX, and QA
- Apply a directed change to an existing application

## Prerequisite Knowledge

- Completed Beginner React JS (react100) or equivalent
- Comfortable building components with props, state, and effects
- Able to consume a JSON API from the browser
