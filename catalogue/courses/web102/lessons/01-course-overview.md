## Description

You can already write JavaScript. You have declared variables, written functions, looped over arrays, and made a button do something on a page. What you have probably not done is take a written description of something somebody wants, break it into pieces you can finish one at a time, build all of them, fix the parts that come back broken, and hand over a working thing with your name on it. That gap — between knowing the language and delivering a project — is what this course closes.

The work is entirely in the browser. No framework, no server, no build pipeline: vanilla JavaScript, the DOM, `fetch`, `localStorage`, and a static dev server are the whole toolkit, because every one of those is a thing you must understand before a framework can hide it from you. You will spend about two thirds of your hours building rather than reading, and the building is graded on evidence a reviewer can check: a work plan, a commit history, an issue log, a running page.

Three projects carry the course, and they grow. The first is a single self-contained widget built to a specification somebody else wrote. The second adds live data, real failure states, and a round of reported defects you have to track to closure. The third is a portfolio piece you scope yourself and then stand up and demo — because at some point the work stops being finished when the code runs and starts being finished when somebody else understands it.

## Objectives

- Plan a JavaScript project as a sequence of deliverable increments
- Use a team source-control workflow to manage project work
- Build working browser features in JavaScript from a written specification
- Track a reported defect from report through fix to verification
- Present a finished project and explain the decisions behind it

## Prerequisite Knowledge

- Working knowledge of HTML and CSS
- Able to write basic JavaScript: variables, functions, arrays, and objects
