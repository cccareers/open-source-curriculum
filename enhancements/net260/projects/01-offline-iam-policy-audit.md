## Scenario

A. Nkemelu's lesson 03 audit of **clinic-prod** found `ci-deployer` holding `Action "*"` on `Resource "*"` with a static key from 2023. D. Whitfield, the Platform Owner, wants to know whether the same thing could creep back in, and asks you for a checker that runs against a weekly IAM export and flags the patterns from lesson 03's first two audit passes: **wildcards** and **escalation paths**. Here is the twist that makes it a real audit and not a grep: several principals look powerful but are fine, and one looks harmless but can make itself an administrator.

This project needs **no cloud account**. You work from a synthetic export in AWS-style policy JSON. The stretch goals show how to run the same checker against your own lab account.

## Scope and authorization

- The export is synthetic and generated by the script below. The principal names reuse the course's fictional clinic team.
- If you take the stretch goal and export real IAM data, do it only from **your own lab or sandbox account**, with the written authorization record from lesson 03 at the top of your report. Never enumerate identities in an account you are not explicitly authorized to examine.

## What you will build / produce

1. `audit.py`. It reads every `export/*.json` file and writes `findings.json`, a list of `{principal, type, severity, ...}` objects where `type` is one of `admin-wildcard`, `service-wildcard`, `escalation`, or `static-key`.
2. A passing run of the provided tests.
3. An access-control audit record in the lesson 03 format for the eight principals, with population split human/machine, a specific fix per finding, an owner, and a target date.
4. A narrowed replacement policy, as fenced JSON, for one finding, written using lesson 03's "Narrowing a policy, worked" method.

## Before you start

- Lesson 03: "How a decision is reached", "Pass 1: the wildcards", "Pass 2: the escalation paths", "The audit artifact".
- Python 3.9+ and `pytest`.
- Generate the export:

```python
# make_export.py - writes a synthetic IAM export for clinic-prod (no cloud account needed)
import json, os
os.makedirs("export", exist_ok=True)
P = {
 "ci-deployer": {"type": "machine", "credential": "static-key", "key_created": "2023-02-11",
   "statements": [{"Effect": "Allow", "Action": "*", "Resource": "*"}]},
 "svc-reporting": {"type": "machine", "credential": "workload-identity",
   "statements": [{"Effect": "Allow", "Action": ["s3:GetObject", "s3:ListBucket"],
                   "Resource": ["arn:aws:s3:::clinic-reports", "arn:aws:s3:::clinic-reports/*"]}]},
 "svc-exporter": {"type": "machine", "credential": "workload-identity",
   "statements": [{"Effect": "Allow", "Action": "s3:*", "Resource": "*"}]},
 "svc-ops-launcher": {"type": "machine", "credential": "workload-identity",
   "statements": [{"Effect": "Allow", "Action": ["ec2:RunInstances", "iam:PassRole"], "Resource": "*"}]},
 "a.nkemelu": {"type": "human", "credential": "federated-mfa",
   "statements": [{"Effect": "Allow", "Action": ["cloudtrail:LookupEvents", "iam:Get*", "iam:List*"], "Resource": "*"}]},
 "j.okafor": {"type": "human", "credential": "federated-mfa",
   "statements": [{"Effect": "Allow", "Action": ["iam:CreatePolicy", "iam:AttachUserPolicy"], "Resource": "*"}]},
 "r.adeyemi": {"type": "human", "credential": "federated-mfa",
   "statements": [{"Effect": "Allow", "Action": "iam:CreateAccessKey", "Resource": "*"}]},
 "svc-intake-reader": {"type": "machine", "credential": "workload-identity",
   "statements": [{"Effect": "Allow", "Action": "s3:GetObject", "Resource": "arn:aws:s3:::clinic-intake/*",
                   "Condition": {"Bool": {"aws:SecureTransport": "true"}}}]},
}
for name, p in P.items():
    json.dump({"principal": name, **p}, open(f"export/{name}.json", "w"), indent=1)
print(f"wrote {len(P)} principals to export/")
```

## Milestones

1. **Read before coding (45 min).** Open each JSON file and classify the principal by hand: admin, admin-equivalent through escalation, over-broad but not escalating, or fine. Write one sentence per principal. Your code must reproduce your reasoning, not the other way round.
2. **Pass 1, wildcards (1 h).** Flag `Action "*"` with `Resource "*"` as CRITICAL. Flag a service-wide wildcard (`s3:*`) on `Resource "*"` as HIGH. Do **not** flag read-only wildcards such as `iam:Get*`/`iam:List*` as escalation. They are broad reads, which you may still mention in your record at a lower severity with a reason.
3. **Pass 2, escalation (1 h).** Encode lesson 03's escalation table as a set of actions. Include the "pass a privileged identity to a service" pattern: `ec2:RunInstances` together with `iam:PassRole` on `*`.
4. **Credentials (15 min).** Any principal whose `credential` is `static-key` is a finding (lesson 03, "Credentials: the thing that actually leaks").
5. **Tests and write-up (2 h).** Run the suite, then write the audit record and one narrowed policy.

## Acceptance criteria

- [ ] `python3 -m pytest -q test_audit.py` passes all seven tests.
- [ ] `svc-reporting`, `svc-intake-reader`, and `a.nkemelu` produce **no** findings. Precision matters (lesson 07: "an alert that fires 200 times a day is a filter someone will disable").
- [ ] Every finding in your audit record has the principal, the grant **and its scope**, evidence, a specific fix (not "apply least privilege"), an owner, and a target date.
- [ ] Your narrowed policy uses named actions, named resources, and at least one condition, and comes with the two-sentence change-ticket justification from lesson 03.
- [ ] Your record includes a "not examined" section that names at least resource policies (bucket and key policies), permission boundaries and organization-level denies, and the pipeline escalation path. This checker cannot see any of them.

## Automated checks

Save as `test_audit.py`:

```python
# run: python3 make_export.py && python3 audit.py && python3 -m pytest -q test_audit.py
import json
F = json.load(open("findings.json"))
def kinds(p): return {f["type"] for f in F if f["principal"] == p}
def test_admin_wildcard_and_static_key():
    assert {"admin-wildcard", "static-key"} <= kinds("ci-deployer")
    assert any(f["severity"] == "CRITICAL" for f in F if f["principal"] == "ci-deployer")
def test_service_wildcard():
    assert "service-wildcard" in kinds("svc-exporter")
def test_passrole_escalation():
    assert "escalation" in kinds("svc-ops-launcher"), "RunInstances + PassRole on * is admin-equivalent"
def test_policy_attach_escalation():
    assert "escalation" in kinds("j.okafor")
def test_access_key_escalation():
    assert "escalation" in kinds("r.adeyemi")
def test_read_only_and_scoped_principals_are_clean():
    for p in ("svc-reporting", "svc-intake-reader", "a.nkemelu"):
        assert kinds(p) == set(), f"{p} should have no findings (read-only or tightly scoped)"
def test_every_finding_has_severity():
    assert all(f.get("severity") in {"CRITICAL", "HIGH", "MEDIUM", "LOW"} for f in F)
```

## Rubric

| Criterion | Developing | Meets | Exceeds |
|---|---|---|---|
| Wildcard detection | Flags read-only wildcards as escalation | Admin and service wildcards correctly separated | Adds `NotAction` handling (an Allow with `NotAction` is a near-wildcard) with a test |
| Escalation detection | Only literal `iam:*` | Lesson 03 table encoded, including PassRole | Handles `Resource` scoping (PassRole limited to one role ARN is not flagged) with a test |
| Audit record | Tool output pasted | Lesson 03 format, owners and dates | Adds usage evidence fields and explains how you would populate them from audit logs |
| Narrowed policy | Still uses wildcards | Named actions, named resources, a condition | Includes the denial-watch query you would run after deploying it |
| Limits | None stated | "Not examined" covers resource policies, boundaries, org denies, and the pipeline | Explains why an explicit deny elsewhere could make a flagged grant harmless, and how you would check |

## Instructor notes

- The reference solution used while drafting produced exactly the expected findings and passed all seven tests.
- Common pitfall: learners flag `iam:Get*` as escalation because it starts with `iam:`. Ask them which row of the escalation table it matches.
- To extend difficulty, add a principal with `iam:PassRole` scoped to a single low-privilege role ARN, which should **not** be flagged, and a matching test.
- Azure/GCP variant: the same exercise works with role assignments plus scope (`/subscriptions/...` vs. a resource group) and the `roles/editor` basic role. Swap the export format and the wildcard rules.
