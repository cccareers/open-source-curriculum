## Scenario

You triaged Thursday at **Meridian Freight Brokerage** by hand in the lesson 08 project. The shift lead liked the report and asked the obvious follow-up: *"Can you turn the method into something that runs every morning?"* You get Friday's connection log — 676 Zeek-style records from the same `10.14.<zone>.0/24` network — and you write a small Python triage script that encodes four of the lesson 02 and lesson 05 patterns: **periodic small check-ins**, **internal fan-out of failed connections**, **DNS sent to a resolver that is not yours**, and **large uploads that are not the documented backup**. The acceptance test rewards precision: the day contains decoys, and a script that flags them fails.

This is supplementary to the lesson 08 project, not a replacement: a script finds candidates; the narrated, evidence-backed finding is still your job.

## Scope and authorization

- The data is **synthetic**, generated by a seeded script below; every address is RFC 1918 or a documentation range (`192.0.2.0/24`, `198.51.100.0/24`, `203.0.113.0/24`) except one well-known public resolver address (`9.9.9.9`) used as a label. No real organization's traffic is involved.
- If you later run your script on real flow data, do it only on networks you own or administer, with written authorization covering the data source; flow logs reveal who talked to whom and are privacy-relevant (lesson 02, "Full packet capture").

## What you will build / produce

1. `triage.py` — reads `conn.log` (tab-separated, header row) and writes `findings.json`: a list of objects with a `type` of `beacon`, `fanout`, `external_dns`, or `large_upload`, plus the fields the tests check.
2. A passing run of the provided test suite.
3. For each finding, a lesson 02-style narration sentence and a lesson 05-style handoff note (under 120 words each).
4. A half-page "what my script cannot see" note.

## Before you start

- Lesson 02 ("A method for narrating a conversation", "Three flows, narrated"), lesson 05 ("Interpreting an alert"), and the lesson 08 runbook facts — the same infrastructure applies on Friday: resolvers `10.14.40.10`/`.11`, backup appliance `10.14.80.5` pulling from servers 01:00–04:00, business hours 07:00–18:00.
- Python 3.9+ and `pytest` (`pip install pytest`).
- Save and run the generator. Everyone with the same seed gets the same day.

```python
# make_day.py - synthetic Meridian Freight flow + DNS logs for Friday 13 March 2026 (seeded)
import random
random.seed(110)
conn, dns = [], []
def c(t, oh, op, rh, rp, proto, svc, dur, ob, rb, st): conn.append((t, oh, op, rh, rp, proto, svc, dur, ob, rb, st))
def hms(s): return f"{s//3600:02d}:{s%3600//60:02d}:{s%60:02d}"
staff = [f"10.14.30.{i}" for i in range(40, 70)]
# routine background: staff to internal apps, file server, internal DNS, web
for _ in range(600):
    h = random.choice(staff); t = random.randint(7*3600, 18*3600)
    kind = random.random()
    if kind < 0.4: c(hms(t), h, random.randint(49152, 65535), "10.14.40.22", 443, "tcp", "ssl", round(random.uniform(1, 90), 2), random.randint(2000, 40000), random.randint(20000, 900000), "SF")
    elif kind < 0.7: c(hms(t), h, random.randint(49152, 65535), "10.14.40.20", 445, "tcp", "smb", round(random.uniform(0.5, 30), 2), random.randint(1000, 20000), random.randint(5000, 3000000), "SF")
    elif kind < 0.85: c(hms(t), h, random.randint(49152, 65535), "10.14.40.10", 53, "udp", "dns", 0.02, 70, 130, "SF")
    else: c(hms(t), h, random.randint(49152, 65535), f"198.51.100.{random.randint(1,250)}", 443, "tcp", "ssl", round(random.uniform(0.5, 60), 2), random.randint(1000, 30000), random.randint(5000, 4000000), "SF")
# documented: backup appliance pulls 01:00-04:00
for i in range(6): c(hms(3600 + i*1500), "10.14.80.5", 41000+i, "10.14.40.20", 445, "tcp", "smb", 1200.0, 9000, 9_000_000_000, "SF")
# PLANTED 1: beacon from 10.14.30.52 to 203.0.113.77:443 every 300 s, 09:00-12:00, small symmetric
for k in range(36): c(hms(9*3600 + k*300 + random.randint(0, 1)), "10.14.30.52", 50000+k, "203.0.113.77", 443, "tcp", "ssl", 1.03, 1190 + random.randint(-3, 3), 846 + random.randint(-3, 3), "SF")
# decoy: update agent from many hosts once each to vendor CDN (not periodic per host)
for h in staff[:20]: c(hms(random.randint(8*3600, 9*3600)), h, random.randint(49152, 65535), "192.0.2.10", 443, "tcp", "ssl", 4.0, 2000, 3_000_000, "SF")
# PLANTED 2: internal fan-out S0 from 10.14.30.63 to 12 servers on 3389 within 5 s
for i in range(12): c(hms(14*3600 + 20*60 + i//3), "10.14.30.63", 52000+i, f"10.14.40.{20+i}", 3389, "tcp", "-", 0.0, 0, 0, "S0")
# PLANTED 3: external DNS bypass from 10.14.60.31 to 9.9.9.9
c("10:44:10", "10.14.60.31", 40001, "9.9.9.9", 53, "udp", "dns", 0.04, 68, 120, "SF")
# PLANTED 4: large upload 10.14.30.47 -> 192.0.2.99:443 at 19:12 (after hours), 3.2 GB out
c("19:12:40", "10.14.30.47", 55201, "192.0.2.99", 443, "tcp", "ssl", 1900.2, 3_200_000_000, 81_000, "SF")
conn.sort(key=lambda r: r[0])
with open("conn.log", "w") as f:
    f.write("ts\tid.orig_h\tid.orig_p\tid.resp_h\tid.resp_p\tproto\tservice\tduration\torig_bytes\tresp_bytes\tconn_state\n")
    for r in conn: f.write("\t".join(map(str, r)) + "\n")
print(f"wrote {len(conn)} connection records")
```

## Milestones

1. **Baseline first (45 min).** Before coding, write down what normal looks like for this network from the runbook facts. Every rule your script applies must trace to a sentence in that baseline — for example, "internal hosts resolve names only through `10.14.40.10` and `10.14.40.11`".
2. **Beacon detection (1.5 h).** Group outbound conversations by (internal source, external destination, destination port). For groups of six or more, compute the gaps between start times. A beacon has a **regular** interval (low spread relative to the median) and **small** payloads. Measure; do not eyeball (lesson 08 hint: "Regularity is the strongest single signal available to you").
3. **Fan-out detection (45 min).** Count distinct internal destinations per source among `S0`/`REJ` records. Pick a threshold and justify it against the baseline.
4. **External DNS (30 min).** Port 53 to anything other than the two internal resolvers, from anything other than the resolvers themselves (they forward externally by design).
5. **Large uploads (45 min).** `orig_bytes` far exceeding `resp_bytes`, above a size threshold, excluding the documented backup pair.
6. **Run the tests and write up (1.5 h).**

## Acceptance criteria

- [ ] `python3 -m pytest -q test_triage.py` passes all six tests.
- [ ] Every threshold in `triage.py` has a comment citing the baseline sentence that justifies it.
- [ ] Each of the four findings has a narration sentence in lesson 02 form (endpoints, direction, service, volume and shape, outcome, baseline comparison).
- [ ] The "cannot see" note names at least two blind spots (e.g., east-west traffic that never crossed the sensor; content of the TLS sessions; which *process* on `10.14.30.52` made the check-ins) and the data source that would close each.

## Automated checks

Save as `test_triage.py`. It reads `findings.json`, so run your script first.

```python
# test_triage.py - run: python3 make_day.py && python3 triage.py conn.log && python3 -m pytest -q test_triage.py
import json
F = json.load(open("findings.json"))
def of(t): return [f for f in F if f["type"] == t]
def test_beacon_found_with_interval():
    b = [f for f in of("beacon") if f["host"] == "10.14.30.52"]
    assert b and b[0]["dest"].startswith("203.0.113.77") and 290 <= b[0]["interval_s"] <= 310
def test_no_beacon_false_positives():
    assert all(f["host"] == "10.14.30.52" for f in of("beacon")), "one-off update downloads are not beacons"
def test_internal_fanout():
    assert any(f["host"] == "10.14.30.63" and f["targets"] >= 10 for f in of("fanout"))
def test_external_resolver():
    assert [(f["host"], f["resolver"]) for f in of("external_dns")] == [("10.14.60.31", "9.9.9.9")]
def test_upload_found_backup_ignored():
    ups = of("large_upload")
    assert any(f["host"] == "10.14.30.47" for f in ups)
    assert not any(f["host"] == "10.14.80.5" for f in ups), "documented backup window must not be flagged"
def test_total_findings_is_precise():
    assert len(F) == 4, f"expected exactly 4 findings, got {len(F)} - precision matters as much as recall"
```

The last test is the one people resent and the one that matters: twenty staff laptops each fetch an update from the same CDN once, and the backup appliance moves 9 GB six times overnight. A script that flags those is the "console that cries wolf" from lesson 05.

## Instructor notes

- The generator is seeded (`random.seed(110)`); a reference solution produced exactly four findings and passed all six tests during drafting.
- Common pitfall: computing the beacon interval across *all* outbound flows from a host rather than per destination; the decoy CDN fetches then look periodic in aggregate.
- Non-coding variant: give learners `findings.json` and grade only the narrations, handoff notes, and blind-spot note.
