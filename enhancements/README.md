Lesson edits are body-only. Typical edits: fixing arithmetic or a factual error in a worked example, defining a term before first use, correcting a code sample that would fail if copied, and a short "Check your understanding" block at the end of a lesson. Each course's `review.md` lists every edit under "Changes applied".

Drafts in `enhancements/` sit outside `catalogue/` on purpose. The course player renders every Markdown file under a course folder as a lesson, so nothing here reaches learners until an editor promotes it.

## Cross-cutting findings

These came up in many pathways. They are the highest-leverage follow-ups.

1. **Worked examples that contradict themselves.** The most common defect by far: totals that do not add up, percentages that disagree with the table beside them, code samples that fail as written. Most were fixed in place. Where a fix cascades through several lessons it was logged instead — see "Open questions" in each review.
2. **Running scenarios that drift between lessons.** The same fictional company or case changes facts from one lesson to the next (dates, headcounts, prices, names). Examples: dm201, dm230, dm350, cyb120, cyb130, the "Meridian" client shared by sn330/sn350/sn360, the se310 seat count. An owner needs to pick the canonical facts; a per-course "scenario bible" would prevent recurrence.
3. **Referenced images that do not exist.** Many lessons link `img/...` diagrams that are not in the repo, and `course.json` `assets` lists describe diagrams nobody has drawn. Many of the new animation storyboards double as specs for these.
4. **Version- and vendor-sensitive content.** Express 5 (now the npm default) breaks routes in node101/ops200; ad-platform, GA4, ServiceNow release, cloud console, LLM model/pricing details all drift. Flagged per course rather than rewritten.
5. **Time-sensitive policy and law.** Medi-Cal and CHW certification (CHW), GDPR/CCPA/EU AI Act and state automated-decision rules (ai350), HIPAA proposed rule (cyb150). Flagged for a qualified reviewer; no new legal or clinical specifics were added.
6. **Thin self-assessment.** Few lessons had a way for learners to check themselves. Many now end with "Check your understanding"; no course has answer keys for its practice items yet.
7. **Coding projects without runnable checks.** CONTRIBUTING asks for learner-runnable tests. Every new coding project ships an acceptance-test sketch; most were run against a throwaway reference solution.

## Suggested next steps

1. Owner decisions on the "Open questions" sections (scenario facts, policy items).
2. Produce media: start with animation storyboards that also replace missing `img/` diagrams.
3. Promote projects: move approved briefs into `catalogue/courses/<id>/` (and add them to `course.json` as `kind: project` lessons) once reviewed.
4. Subject-matter review for CHW (clinical/legal) and ai350 (legal) before learners see edits there.
